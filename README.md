# ПОС — преподавательская оценка студентов

Консольное приложение `pos` для ведения ведомости одного курса. Ведомость содержит студентов, рубрикатор и выставленные оценки. Итоги можно посмотреть в консоли и выгрузить в CSV.

## Запуск

Требуется Go 1.22 или новее. Проект использует стандартную библиотеку Go.

```bash
go run ./cmd/pos
```

В консоли введите `help`, чтобы увидеть команды. Идентификатор вводится одним словом. Имя, название критерия и путь к файлу могут содержать пробелы, кавычки вокруг них не нужны. Для дробной части используйте точку.

### Пример сеанса

```text
student-add s1 Анна Иванова
student-add s2 Борис Петров
criterion-add exam 20 3 Экзамен
criterion-add project 10 1 Командный проект
students
criteria
grade-set s1 exam 10
grade-set s1 project 10
grades s1
total s1
grade-edit s1 exam 20
total s1
grade-cancel s1 project
total
export totals.csv
exit
```

Итог Анны последовательно составит 62,50%, 100,00% и 75,00%. Итог Бориса составит 0,00% при пустом списке оценок. Команда `total` показывает итоги всех студентов, а `total s1` — итог одного студента. Вместе с результатом выводится число оценённых критериев. В том же порядке по идентификаторам студентов экспорт формирует CSV с колонками `student_id`, `student_name`, `total_percent`, `graded` и `criteria`. Существующий файл защищён от перезаписи.

Репозиторий хранит ведомость в памяти до завершения процесса. CSV сохраняет отчёт по итогам сеанса.

## Правила расчёта

Балл по критерию переводится в долю от его максимума. Итог в процентах равен `100 × сумма(вес × доля) / сумма(вес)` по критериям, участвующим в расчёте. Вес задаёт относительную важность критерия, поэтому сумма весов может быть любой. Перед суммированием веса делятся на наибольший участвующий вес, чтобы избежать переполнения при сложении. Консоль и CSV округляют итог до двух знаков при выводе.

| Режим запуска | Как учитывается пропуск | Когда итог не определён |
| --- | --- | --- |
| `go run ./cmd/pos` или `-missing=zero` | В числителе ноль, вес входит в знаменатель | Рубрикатор пуст |
| `go run ./cmd/pos -missing=ignore` | Критерий целиком исключается из формулы | У студента нет ни одной оценки |

Выставленный ноль учитывается в обоих режимах. В CSV поле `total_percent` для неопределённого итога остаётся пустым. Исправление, отмена оценки и добавление критерия влияют на следующий расчёт.

## Доменная модель

| Термин предметной области | Тип и роль |
| --- | --- |
| Студент | `Student` — Entity с идентификатором в списке курса |
| Критерий рубрикатора | `Criterion` — Entity с идентификатором, названием, максимумом и весом |
| Оценка | `Evaluation` — факт выставления балла, идентифицируемый парой «студент и критерий» |
| Балл | `Score` — Value Object без собственной идентичности. Один и тот же балл может входить в разные оценки |
| Ведомость курса | `Gradebook` — корень агрегата, который контролирует состав списков и операции с оценками |
| Итог | `Total` — результат Domain Service `Calculator` для текущего снимка ведомости |

В одном агрегате собраны данные, которые проверяются совместно при выставлении оценки. Состояние хранится в закрытых полях. Добавление студента и критерия проверяет обязательные поля и уникальность идентификаторов в своём списке. Максимум и вес должны быть конечными и строго положительными.

Выставление и исправление проверяют наличие студента и критерия и диапазон балла `[0, максимум]`. При выставлении повторная запись отклоняется. При исправлении и отмене запись должна существовать. Неуспешная операция оставляет ведомость прежней. После отмены ту же пару можно оценить снова.

## Ports and Adapters

```text
cmd/pos → composition → adapters → application → domain
                             └──────────────────→ domain
```

| Пакет | Ответственность |
| --- | --- |
| `internal/domain` | Модель, инварианты и взвешенный расчёт |
| `internal/application` | Фасад сценариев и выходные порты `GradebookRepository` и `TotalExporter` |
| `internal/adapters/console` | Разбор команд, вызов сценариев и отображение результата |
| `internal/adapters/memory` | Реализация репозитория. Чтение возвращает снимок, обновление публикуется только при успехе |
| `internal/adapters/csvexport` | Преобразование результатов в CSV и запись файла |
| `internal/composition`, `cmd/pos` | Ручной DI-контейнер и точка входа |

Консоль вызывает публичные методы фасада приложения. Фасад читает и обновляет агрегат через порт репозитория. Для экспорта он получает итоги тем же способом, что и для команды `total`, и передаёт строки через порт экспорта. `composition.New` выбирает стратегию расчёта, создаёт адаптеры и передаёт их через конструкторы. Так способ хранения и формат выгрузки можно менять на краю приложения.

### Паттерны GoF

| Группа | Паттерн и применение |
| --- | --- |
| Порождающий | **Фабрика**. Закрытый метод `Gradebook.newEvaluation` создаёт оценку после сверки с рубрикатором и проверки диапазона. Выставление и исправление используют одни правила создания |
| Структурный | **Facade**. `application.Gradebook` даёт консоли единый API. Работа с репозиторием, доменным сервисом и экспортом выполняется внутри сценариев |
| Поведенческий | **Strategy**. `MissingAsZero` и `IgnoreMissing` определяют, участвуют ли критерии без оценки в формуле. `Calculator` использует общий взвешенный расчёт, а контейнер выбирает стратегию на старте |

## Проверки

```bash
gofmt -l cmd internal
go vet ./...
go build ./...
go test ./...
go test -coverpkg=./... -coverprofile=coverage.out ./...
go tool cover -func=coverage.out
```

Тесты домена проверяют границы баллов, обязательные поля, ссылки на участников ведомости, обе стратегии и пересчёт после изменения оценок. Тесты репозитория проверяют откат, изоляцию снимков и параллельные обновления. Сквозные тесты запускают консоль через точку входа с реальным DI-контейнером и проверяют CSV, сообщения об ошибках и продолжение сеанса после неверной команды.
